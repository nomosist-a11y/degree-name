# qcsuite アイデア一覧(フェーズ 0)

前提は「**音の良し悪しの判断は人、手間のかかる操作・比較・整理・記録は機械**」。
AI に音を決めさせる機能は作らない。機械がやるのは、同じ条件でそろえて鳴らす、
並べる、名前を伏せる、記録する、整理する、戻せるようにする、の部分だけ。

## 評価の付け方

| 項目 | 意味 |
|---|---|
| 価値 | 高 / 中 / 低。ギタリストの日々の作業がどれだけ楽になるか |
| 工数 | S(半日) / M(1〜2 日) / L(3 日以上)。モックとテスト込み |
| 実機依存度 | 低: バックアップの JSON やファイルだけで動く。中: 読み取りだけ実機が要る。高: 書き込みかリアンプが要る |
| リスク | 低 / 中 / 高。既存のプリセットや本体設定を壊す可能性、誤った結果を信じてしまう可能性 |

## 除外したもの(実機で不可能、または安全ルールに反する)

| 案 | 除外の理由 |
|---|---|
| キャプチャーをパソコンから差し替えて聴き比べる | `set_capture` の file_name とキャプチャーブロックのパラメーターは書けるが音に反映されない(事実 1) |
| キャビのマイクをパソコンから切り替えて比較する | "ir selector" などの文字列パラメーターは音に反映されない(事実 1) |
| 未所有プラグインの試奏 | 置けるが音は素通し(事実 1)。比較に混ぜると誤った結論になる |
| プリセットの名前をその場で変える | 名前変更の命令がない(事実 5)。コピー + 保存し直しで代用するしかなく、タグが消える |
| タグを保ったままのコピー | `save_current_preset` がタグを運べない(pyquadcortex の docstring) |
| Global EQ で部屋に合わせて自動補正 | 安全ルールで Global EQ は呼ばない |
| 入出力レベル・USB 設定の自動調整 | 安全ルールで本体全体の I/O 設定は呼ばない |
| パソコン主導の Neural Capture 作成 | `show_capture_dialog` は UI を描かないホストが応答すると本体が宙に浮く(docstring)。UI 実装は対象外 |
| AI による音の自動合わせ込み | 前回、品質が低かった。判断は人に残す方針 |

## 必須機能(依頼の 1〜10)

| # | 機能 | 価値 | 工数 | 実機依存度 | リスク | メモ |
|---|---|---|---|---|---|---|
| 1 | プリセット管理(一覧・検索・並べ替え・重複検出・コピー計画・チェーン表示) | 高 | M | 中 | 中 | コピーは本体の音が切り替わり、タグが消える。計画表示と確認を必須にする |
| 2 | バックアップと変更履歴(正規化 JSON + git + 差分 + sandbox への復元) | 高 | M | 中 | 中 | 読み込みで音が切り替わる。復元は数値パラメーターと構造のみで、キャプチャー・マイク・未所有プラグインは鳴らない |
| 3 | 音量そろえ(LUFS 測定 + OUTPUT 補正案 + sandbox コピーへの適用) | 高 | M | 高 | 中 | 補正は行の Lane Output VOLUME(-40〜+12 dB)で行う |
| 4 | ブラインド比較(トーナメント、Elo、ブラウザ再生) | 高 | M | 中 | 低 | 名前を伏せ、音量をそろえ、素通しを除外してから並べる |
| 5 | 言葉で操作するパネル(ルール + Claude API、履歴と取り消し) | 中 | M | 高 | 中 | 変換は操作だけ。音の評価はしない。保存はしない |
| 6 | 総当たり(スイープ)の汎用化 | 高 | M | 高 | 低 | 宣言的な仕様、素通し除外、JSONL で再開、結果を 4 に渡す |
| 7 | プリセットの資料化(チェーン図とノブの HTML / PDF) | 中 | S | 低 | 低 | バックアップ JSON から作れる |
| 8 | セットリストと MIDI(配置計画 + PC 番号表) | 高 | M | 中 | 中 | 配置の実行は dry-run が既定。CC#32 の番号割り当ては実機で要確認 |
| 9 | 一括リアンプ(DI × プリセット、Logic 向けステム) | 高 | M | 高 | 低 | 遅延をそろえて書き出す |
| 10 | 研究メモ(パソコンから切り替わらない原因の仮説と安全な実験手順) | 中 | S | 低 | 低 | 実験はローカルで |

## 優先順位

1. 共通基盤(安全ルール、ロック、再試行、モック、ジョブ)
2. 必須機能 1〜9 と研究メモ 10、および必須扱いに上げた A・D・E・J・K・N・R
3. そのほかの追加案 B・C・G・H・I・L・M・O・P
4. 保留・見送り(F・Q・S・T・U・V)は最終報告の保留リストに載せる

(2026-10-27 にユーザーの指示で優先度を変更: A・D・E・J・K・N・R を必須扱いに、F と U は作らない。
同時に、同時録り(H)と遅延(I)についての実機の事実を反映した。)
