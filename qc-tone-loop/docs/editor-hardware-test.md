# エディター 実機テスト手順書

エディター(`qcsuite serve` の「エディター」タブ)は、モック(FakeQuadCortex)だけで作って確かめました。
2026-11-10 に、表示と書き込みを実機で確かめました(下の「実機での確認記録」)。ただし本体の値の読み戻しで確かめただけで、**音と本体の画面での見え方は、プレイヤーが聴いて・見て確かめるまで未確認**です。この手順書は、プレイヤーの合図(「実機で試して」)のあと、
プレイヤーと Claude Code が一緒に、上から順に実行するためのものです。

- 所要時間: 30〜45 分
- 書き込むのは本体の「今のグリッド」だけです(保存はしません)。手順 1 で sandbox に保存するときだけ、計画(dry run)を読み上げて同意をもらいます。
- 失敗しても、その場で直そうとしません。「記録のしかた」に沿って書き留め、止まってプレイヤーに聞きます。

## 確かめたいこと(モックでは分からないこと)

- **A. skew とつまみの値の関係**: エディターは、本体に送る 0〜1 の値を「(値 − 最小) ÷ (最大 − 最小)」の直線で計算し(pyquadcortex の `real=`)、つまみの角度だけに skew を使っています。本体が 0〜1 を skew 済みの位置として扱っているなら、skew の付いたつまみで本体の値がずれます(手順 2-8、3-8)。
- **B. スイッチの選択肢の名前**: スイッチは、プリセットの `dynamic_steps` に入っている選択肢の名前でしか書きません。本体が普通のスイッチ(PEAK など)にも名前を入れているかは未確認です。入っていなければ、エディターではそのスイッチは表示だけになります。
- **C. ドラッグ中の送信間隔**: 約 0.1 秒ごとに 1 つずつ送り、前の書き込みが終わるまで次は送りません。本体が詰まらないか(手順 3-4、2-11)。
- **D. ModelRepo の取得**: 非公開 API `_fetch_model_repo` が CorOS 4.1.0 で動くか(手順 2-2)。
- **E. キャブのつまみ**: 実機のキャブは「Default Cabsim」の複製で、pyquadcortex のカタログでは名前で扱えないため、エディターでは表示だけです。値の読み取り(複製元の位置から読む)が正しいか(手順 2-9)。

## 記録のしかた

手順ごとに 1 行、次の形で書き、最後にプレイヤーに読み上げます。

```
手順 3-8: 失敗。エディター -12.0 dB、本体 -31.4 dB(OUTPUT、Brit 2203)。音は本体の表示どおり。
手順 2-6: 成功。
```

実機がモックと違う動きをしたら、モック(`qcsuite/device/fake.py`)が間違っています。テストやモックをその場で書き換えず、
「本体がどう動いたか(数値、メッセージ)」を書き留め、モックの修正は別に提案します。
